# 11 - Modelo Lógico

Nove tabelas em cinco schemas, um por módulo
([ADR 0005](../../02-arquitetura/adr/0005-schema-por-modulo-postgres.md)).
É o modelo **v3** (simplificado). Para o desenho veja [10 - DER](10-der.md).

> **Estado do modelo.** A v3 é a modelagem de referência. O DDL em
> [12 - DDL](../implementacao/12-ddl-schema.md), o `schema.sql` e o seed
> descrevem a v2 (15 tabelas) e serão alinhados à v3 numa migration futura.
> Até lá os dois documentos divergem de propósito.

Convenção: **PK** chave primária, **FK** chave estrangeira, **UQ** unicidade,
**NN** obrigatória. A coluna *Regra* cita a RN de
[08 - Regras de Negócio](../../01-negocio/08-regras-de-negocio.md). Chaves
primárias são `integer GENERATED BY DEFAULT AS IDENTITY`.

## Módulo `identidade`

### `identidade.usuario`

Pessoa cadastrada. Existe uma vez, independente de quantos grupos integra. O
login é externo (Google), então o sistema não guarda senha nem credencial: a
identidade é o e-mail (RN05).

| Coluna | Tipo | Chave | Restrição | Regra |
| --- | --- | --- | --- | --- |
| `id_usuario` | `IDENTITY` | PK | | |
| `nome` | `VARCHAR(100)` | | NN | |
| `email` | `VARCHAR(120)` | UQ | NN | RN05 |
| `apelido` | `VARCHAR(50)` | | NN — deliberadamente **não** único | |
| `data_cadastro` | `TIMESTAMPTZ` | | NN, default `CURRENT_TIMESTAMP` | |

## Módulo `grupos`

### `grupos.grupo_amigos`

| --- | --- | --- | --- | --- |
| `id_grupo` | `IDENTITY` | PK | | |
| `nome` | `VARCHAR(80)` | | NN | |
| `descricao` | `VARCHAR(255)` | | | |
| `id_criador` | `INT` | FK → `usuario` | NN | RN25 |
| `data_criacao` | `TIMESTAMPTZ` | | NN, default `CURRENT_TIMESTAMP` | |

### `grupos.membro_grupo`

Associativa usuário × grupo. Carrega o papel e o saldo de CP, que é **por
grupo**.

| Coluna | Tipo | Chave | Restrição | Regra |
| --- | --- | --- | --- | --- |
| `id_membro` | `IDENTITY` | PK | | |
| `id_grupo` | `INT` | FK → `grupo_amigos`, UQ | NN, `ON DELETE CASCADE` | |
| `id_usuario` | `INT` | FK → `usuario`, UQ | NN, `ON DELETE CASCADE` | |
| `papel` | `VARCHAR(20)` | | NN, default `MEMBRO`, `chk_membro_papel`: `ADMIN`, `MEMBRO` | RN25 |
| `saldo_cp` | `INT` | | NN, default `100`, `chk_membro_saldo`: `>= 0` | RN06, RN08 |
| `data_entrada` | `TIMESTAMPTZ` | | NN, default `CURRENT_TIMESTAMP` | |

`unq_membro_grupo (id_grupo, id_usuario)` impede entrada duplicada. `saldo_cp`
é saldo **materializado**: a fonte da verdade é `economia.transacao_cp`, e a
view `economia.vw_reconciliacao_saldo` (sempre vazia) detecta divergência.

### `apostas.participante_aposta`

Associativa usuário × aposta.

| Coluna | Tipo | Chave | Restrição | Regra |
| --- | --- | --- | --- | --- |
| `id_participante` | `IDENTITY` | PK | | |
| `id_aposta` | `INT` | FK → `aposta`, UQ | NN, `ON DELETE CASCADE` | |
| `id_usuario` | `INT` | FK → `usuario`, UQ | NN | RN09 |
| `papel_aposta` | `VARCHAR(20)` | | NN, `chk_participante_papel`: `DESAFIANTE`, `DESAFIADO`, `APOSTADOR` | RN09 |
| `escolha` | `VARCHAR(20)` | | NN, `chk_participante_escolha`: `VAI_CUMPRIR`, `NAO_VAI_CUMPRIR` | |
| `data_aceite` | `TIMESTAMPTZ` | | NN, default `CURRENT_TIMESTAMP` | RN18 |

Duas restrições cobrem a RN09: `unq_participante_aposta (id_aposta, id_usuario)`

`unq_aposta_papel_unico (id_aposta, papel_aposta) WHERE papel_aposta IN
('DESAFIANTE','DESAFIADO')` limita a um de cada papel único sem restringir a
quantidade de `APOSTADOR`.

## Módulo `validacao`

### `validacao.evidencia`

Prova de cumprimento enviada pelo desafiado. Uma aposta admite até cinco, em
sequência.

| Coluna | Tipo | Chave | Restrição | Regra |
| --- | --- | --- | --- | --- |
| `id_evidencia` | `IDENTITY` | PK | | |
| `id_aposta` | `INT` | FK → `aposta`, UQ | NN, `ON DELETE CASCADE` | |
| `id_usuario` | `INT` | FK → `usuario` | NN | |
| `ordem` | `INT` | UQ | NN, `chk_evidencia_ordem`: `BETWEEN 1 AND 5` | RN10 |
| `tipo_midia` | `VARCHAR(20)` | | NN, `chk_evidencia_midia`: `FOTO`, `VIDEO`, `LINK`, `TEXTO` | |
| `url_comprovante` | `VARCHAR(500)` | | NN | RN22 |
| `comentario` | `TEXT` | | | |
| `status` | `VARCHAR(20)` | | NN, default `EM_VOTACAO`, `chk_evidencia_status`: `EM_VOTACAO`, `ACEITA`, `RECUSADA`, `EXPIRADA` | RN13 |
| `data_envio` | `TIMESTAMPTZ` | | NN, default `CURRENT_TIMESTAMP` | |
| `data_limite_votacao` | `TIMESTAMPTZ` | | NN, `chk_evidencia_votacao`: `> data_envio` | RN11 |
| `data_apuracao` | `TIMESTAMPTZ` | | `chk_evidencia_apuracao`: obrigatória se status ≠ `EM_VOTACAO` | RN13 |

`unq_evidencia_ordem (id_aposta, ordem)` impede duas evidências na mesma
posição da sequência. `status` é um fato gravado uma única vez pela procedure
de apuração, não uma reinterpretação de votos.

### `validacao.jurado_evidencia`

Júri congelado **e** voto, na mesma linha. Uma linha por integrante elegível,
criada no envio da evidência com `voto` nulo; votar é preencher a linha.

| Coluna | Tipo | Chave | Restrição | Regra |
| --- | --- | --- | --- | --- |
| `id_evidencia` | `INT` | PK, FK → `evidencia` | NN, `ON DELETE CASCADE` | RN14 |
| `id_usuario` | `INT` | PK, FK → `usuario` | NN | RN14 |
| `voto` | `VARCHAR(20)` | | Nulo = ainda não votou, `chk_jurado_voto`: `VALIDO`, `INVALIDO` | RN15 |
| `justificativa` | `VARCHAR(255)` | | | |
| `data_voto` | `TIMESTAMPTZ` | | `chk_jurado_voto_data`: preenchida se, e somente se, `voto` preenchido | RN15 |

A PK composta `(id_evidencia, id_usuario)` garante **voto único** (RN04) e
**voto só de quem está no júri** (RN14), sem FK composta. Um trigger recusa
alterar `voto` fora do prazo ou em evidência que não está `EM_VOTACAO` (RN19).
Quórum: `floor(count(*)/2) + 1` sobre as linhas da evidência
([ADR 0008](../../02-arquitetura/adr/0008-quorum-congelado.md)).

## Módulo `economia`

### `economia.transacao_cp`

Ledger append-only de partidas dobradas. Nunca sofre `UPDATE` nem `DELETE`.

| Coluna | Tipo | Chave | Restrição | Regra |
| --- | --- | --- | --- | --- |
| `id_transacao` | `IDENTITY` | PK | | |
| `id_grupo` | `INT` | FK → `grupo_amigos` | NN, `ON DELETE CASCADE` | |
| `id_usuario` | `INT` | FK → `usuario` | Nulo = conta da aposta (escrow) | RN18 |
| `id_aposta` | `INT` | FK → `aposta` | | RN18 |
| `tipo` | `VARCHAR(20)` | | NN, `chk_transacao_tipo`: `CREDITO_INICIAL`, `APOSTA_ESCROW`, `PREMIO`, `ESTORNO`, `RECOMPENSA_VOTO` | RN06, RN12, RN17, RN18, RN23 |
| `valor` | `INT` | | NN, `chk_transacao_valor`: `<> 0` — positivo credita, negativo debita | RN24 |
| `descricao` | `VARCHAR(255)` | | NN | |
| `data_lancamento` | `TIMESTAMPTZ` | | NN, default `CURRENT_TIMESTAMP` | |

`chk_transacao_conta` exige que o lançamento pertença a um usuário ou a uma
aposta; `chk_transacao_escrow` exige `id_aposta` quando o tipo é
`APOSTA_ESCROW`. A imutabilidade é do trigger `trg_transacao_cp_imutavel`
(RN24); estorno é lançamento novo.
